# A11y Fixer

Локальное расширение VS Code для Vue 3 + Vite и Nuxt. Оно поднимает dev-сервер на `127.0.0.1`, проверяет открытую страницу через axe-core и делит нарушения на быстрые, ручные и неоднозначные. Исходники и результаты наружу не отправляются. Быстрая правка записывается только после кнопки в редакторе.

Пустой список нарушений не означает соответствие WCAG.

## Как запустить

Нужен Chrome или Chromium. Если браузер лежит не в обычном месте, задайте `CHROME_PATH`. Без браузера проверка не поднимает dev-сервер.

```bash
npm install
npm --prefix demo install
npm test
npm run check
```

`npm test` гоняет unit-тесты без браузера. `npm run check` дополнительно прогоняет живой аудит временной копии `demo/` и оставляет файлы демо без изменений.

Продуктовый аудит Nuxt 3.21.11:

```bash
npm run test:nuxt
```

Живой аудит Vuetify 3.13.7, Quasar 2.35.5 и Nuxt UI 4.12.2:

```bash
npm run test:libraries
```

Запись в окне VS Code через WorkspaceEdit:

```bash
npm run test:editor
```

Нужны дисплей и локальный VS Code. По умолчанию берётся `/usr/share/code/code`, другой бинарник Electron задаётся `A11Y_VSCODE`. В `npm test` и `npm run check` этот прогон не входит.

Если в `fixtures/nuxt-app` ещё нет зависимостей, эта команда сама выполнит там `npm install`.

В VS Code откройте эту папку, затем Run and Debug и конфигурацию «Запустить A11y Fixer». Откроется окно с папкой `demo`. На панели A11y Fixer выберите область и нажмите «Проверить».

На вкладке быстрых правок виден список. У выбранной строки показан diff, и только после кнопки «Исправить» правка записывается. Можно исправить все сразу и перепроверить. Кнопка «Создать отчёт» в верхней панели записывает `a11y-fixer-report.md` и `a11y-fixer-report.json` и не меняет исходники. «Показать в коде» открывает файл и выделяет найденный фрагмент. Ручные и неоднозначные проблемы расширение не переписывает. Пустой или непустой список не является заключением о соответствии WCAG. Язык панели и отчёта берётся из языка VS Code: русский или английский.

## Что умеет сейчас

- Динамический аудит запущенного приложения. Vite проверяет корень. Nuxt проверяет статические страницы выбранной области и пропускает динамический маршрут без готовой ссылки.
- Статический разбор `.vue` выбранной области, включая страницы, компоненты и layouts, которые эта страница не отрисовала. Он использует Vue-компилятор открытого проекта.
- Точная метка `data-a11y-source-id` для нативного HTML внутри Vue SFC и для разрешённого тега Vuetify, Quasar или Nuxt UI. Такая же строка в другом месте файла сама по себе попаданием не считается: диапазон должен совпасть с узлом AST.
- Быстрые правки только для однозначных атрибутов: `tabindex`, прокручиваемый регион, `autoplay`, запрещённые ARIA-атрибуты, `aria-hidden` на `body`, viewport. Текст `alt`, подписи и доступного имени не придумывается.
- Аудит всего проекта или выбранной папки. Приложение запускается из корня, правки вне области отклоняются.

## Границы

- Кнопка «Проверить» требует `vite.config` или `nuxt.config` и браузер. Панель показывает прогресс по числу страниц и кнопку «Отменить проверку». Отмена оставляет уже собранные результаты. Файл, который ни одна открытая страница не отрисовала, остаётся в результате со статическим происхождением.
- Статический разбор уверенно видит отсутствующий `alt` у `img`, активной `area` и `input type="image"`, пустую кнопку, ссылку с `href`, пустой заголовок, `iframe` без имени и целый `tabindex` больше нуля. Имя и `alt` по-прежнему не придумываются. Быстрая правка есть только у этого `tabindex`.
- Повтор после записи заново запускает оба разбора. Авторизация и состояния интерфейса в эту проверку не входят.
- Из UI-библиотек разобраны только `VBtn`, `VImg`, `QBtn`, `QImg` и `UButton` версий Vuetify 3.13.7, Quasar 2.35.5 и Nuxt UI 4.12.2. Метка ставится на такой тег, если проект его действительно регистрирует. Другой компонент метку не получает. Текст `alt` и доступное имя не придумываются. Быстрый `tabindex` есть у `VBtn` и `QBtn`.
- Слоты, `v-html`, `v-for` и динамические атрибуты автоматически не исправляются.
- Продуктовая регрессия Nuxt закреплена на 3.21.11. Nuxt 4 проверен отдельным экспериментом инструментирования (`npm run experiment:nuxt`, запуск через `nuxt dev`), а не через `startNuxtApp`.
- Повторный аудит Nuxt после правки может увидеть старый бандл: сброс кэша модулей для Nuxt не реализован.
- Открывается одна папка workspace. Отчёты пишутся в `a11y-fixer-report.md` и `a11y-fixer-report.json` и сами файлы не чинят.
- Каталоги из настройки `a11yFixer.excludeDirectories` не входят в область аудита и в быстрые правки. По умолчанию это `node_modules`, `dist`, `build`, `.git`, `.nuxt` и `.output`. Свой список заменяет этот набор. Корень запуска приложения от настройки не меняется.

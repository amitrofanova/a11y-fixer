# Тесты

Раннер — встроенный `node:test`. Отдельный тестовый фреймворк не подключён. TypeScript тестов собирается в `out-test/` отдельным `tsconfig.test.json`. Сборка расширения по-прежнему кладёт только `src` в `out/`.

В этом Node `node --test` запускает переданные файлы. Каталог как единственный аргумент он пытается загрузить как модуль, поэтому скрипты передают `*.test.js`.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm test` | Unit-тесты. Chrome и сеть не нужны. Нужны зависимости `demo/`: `npm --prefix demo install`. |
| `npm run test:vite` | Собирает расширение и гоняет живой аудит временной копии `demo/`. |
| `npm run test:nuxt` | Собирает расширение и гоняет `auditProject` через `startNuxtApp` на Nuxt 3.21.11. |
| `npm run check` | `compile`, затем `npm test`, затем `npm run test:vite`. |
| `npm run experiment:nuxt` | Отдельный прогон метки через `nuxt dev` на Nuxt 3.21.11 и 4.6.4. axe не вызывает. |

`npm run check` не включает Nuxt: старт приложения заметно длиннее unit-цикла. Для приёмки изменений продуктового раннера нужен `npm run test:nuxt`.

Первый `test:nuxt` выполняет `npm install` в `fixtures/nuxt-app`, если там ещё нет `node_modules`. Повторный запуск использует уже установленные пакеты. Версия в тесте обязана быть `3.21.11`.

## Что где проверяется

- `test/unit` — `planApply`, область аудита, маршруты Nuxt, `locateMarker`, Quick Fix, классификация, viewport, `resolveRange`, язык интерфейса, отчёт, отсутствие импорта `vscode` в `src/core` и статический разбор `fixtures/static`.
- `test/integration/vite-audit.test.ts` — прежние сценарии демо: область `src`, пакет правок, поочерёдные правки, переформатирование и повторный аудит. Отдельный сценарий проверяет, что нативная кнопка дочернего SFC сопоставляется с файлом ребёнка.
- `test/integration/nuxt-audit.test.ts` — первый аудит фикстуры: `mappingEnabled`, quick fix `tabindex` в `components/Panel.vue`, ручная пустая кнопка, неоднозначный `v-for`, отсутствие придуманного `alt` или `aria-label`, неизменность исходников, закрытие порта и удаление `node_modules/.a11y-fixer`.

Парсер Vue в unit-тестах берётся из `demo/node_modules` через временный проект. Своей копии `@vue/compiler-sfc` у расширения нет. Фикстуры `fixtures/static` описывают ожидаемые статические находки и случаи, где правки быть не должно.

## Правила прогона

- Vite- и Nuxt-регрессии копируют проект во временный каталог и подключают его `node_modules` символической ссылкой. `demo/` и исходники `fixtures/nuxt-app` после успешного прогона совпадают с состоянием до запуска.
- Отказ `planApply` в unit-тестах не меняет файл. Запись в Vite-регрессии — это `fs` по уже посчитанному тексту во временной копии. Она не заменяет проверку `WorkspaceEdit` в окне редактора.
- Ожидание теста меняется только если сам критерий ошибочен. Сначала объясняется причина, потом правится тест.
- Таймаут интеграционных тестов — 300 секунд на тест, тесты внутри файла идут по одному.

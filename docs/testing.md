# Тесты

Раннер — встроенный `node:test`. Отдельный тестовый фреймворк не подключён. TypeScript тестов собирается в `out-test/` отдельным `tsconfig.test.json`. Сборка расширения по-прежнему кладёт только `src` в `out/`.

В этом Node `node --test` запускает переданные файлы. Каталог как единственный аргумент он пытается загрузить как модуль, поэтому скрипты передают `*.test.js`.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm test` | Unit-тесты. Chrome и сеть не нужны. Нужны зависимости `demo/`: `npm --prefix demo install`. |
| `npm run test:dynamic` | Ошибки запуска: нет браузера, битый исполняемый файл, нет конфига, нет пакета Nuxt. |
| `npm run test:vite` | Собирает расширение и гоняет живой аудит временной копии `demo/`. |
| `npm run test:nuxt` | Собирает расширение и гоняет `auditProject` через `startNuxtApp` на Nuxt 3.21.11. |
| `npm run test:libraries` | Собирает расширение и гоняет живой аудит фикстур Vuetify 3.13.7, Quasar 2.35.5 и Nuxt UI 4.12.2. В `npm test` и `npm run check` не входит. |
| `npm run test:editor` | Открывает окно VS Code и проверяет запись через `WorkspaceEdit`: подтверждение, один пакет правок, область аудита, отказ без `applyEdit`, повторная проверка после `save`. В `npm test` и `npm run check` не входит. |
| `npm run check` | `compile`, затем `npm test`, `npm run test:dynamic` и `npm run test:vite`. |
| `npm run experiment:nuxt` | Отдельный прогон метки через `nuxt dev` на Nuxt 3.21.11 и 4.6.4. axe не вызывает. |

`npm run check` включает unit-тесты, ошибки запуска и Vite. Nuxt и UI-библиотеки в него не входят: старт приложения заметно длиннее unit-цикла. Для приёмки продуктового раннера нужен `npm run test:nuxt`, для Vuetify, Quasar и Nuxt UI — `npm run test:libraries`.

Первый `test:nuxt` выполняет `npm install` в `fixtures/nuxt-app`, если там ещё нет `node_modules`. Повторный запуск использует уже установленные пакеты. Версия в тесте обязана быть `3.21.11`.

Первый `test:libraries` так же ставит зависимости в `fixtures/libraries/vuetify`, `quasar` и `nuxt-ui`, если их ещё нет. Проверяемые версии обязаны быть `3.13.7`, `2.35.5` и `4.12.2`.

## Что где проверяется

- `test/unit` — `planApply`, область аудита, настройка исключений, Markdown- и JSON-отчёты, маршруты Nuxt, `locateMarker`, Quick Fix, классификация, `finalizeIssues`, отказ `UNSAFE` на весь пакет, viewport, `resolveRange`, язык интерфейса, отсутствие импорта `vscode` в `src/core`, статический разбор `fixtures/static`, закрытый каталог Vuetify, Quasar и Nuxt UI, и Webview: `media/panel.js` рисуется в тестовом документе. Проверяются состояние проверки, одна открытая подробность, diff до кнопки «Исправить», ручные и неоднозначные строки без записи, фраза про WCAG и отдельный список вне области.
- `test/editor` — то же окно VS Code, в котором работает расширение. Тест вызывает `applyConfirmedEdits`, который возвращает активация. Отказ не должен вызывать `vscode.workspace.applyEdit`. Успешная правка — один `WorkspaceEdit` по исходным диапазонам, затем `save`, и только после этого повторная проверка.
- `test/integration/library-audit.test.ts` — живой аудит трёх фикстур: пустая icon-кнопка сопоставляется с тегом компонента в SFC пользователя и остаётся ручной, кнопка с видимым текстом правила `button-name` не получает.
- `test/integration/dynamic-errors.test.ts` — отказ до старта сервера, закрытие приложения после неудачного запуска браузера и `NO_NUXT` без оставшегося модуля.
- `test/integration/vite-audit.test.ts` — прежние сценарии демо: область `src`, пакет правок, поочерёдные правки, переформатирование и повторный аудит. Нативная кнопка дочернего SFC сопоставляется с файлом ребёнка. Диапазон совпадает со срезом файла. После закрытия сессии порт свободен.
- `test/integration/nuxt-audit.test.ts` — первый аудит фикстуры и отдельный прогон страницы: статический `/about` открывается, динамический `[id]` без существующей ссылки даёт `NO_ROUTE`.

Парсер Vue в unit-тестах берётся из `demo/node_modules` через временный проект. Своей копии `@vue/compiler-sfc` у расширения нет. Фикстуры `fixtures/static` описывают ожидаемые статические находки и случаи, где правки быть не должно.

## Правила прогона

- Vite-, Nuxt- и библиотечные регрессии копируют проект во временный каталог и подключают его `node_modules` символической ссылкой. `demo/`, исходники `fixtures/nuxt-app` и `fixtures/libraries` после успешного прогона совпадают с состоянием до запуска.
- Отказ `planApply` в unit-тестах не меняет файл. Запись в Vite-регрессии — это `fs` по уже посчитанному тексту во временной копии. Окно редактора проверяет отдельная команда `npm run test:editor`: нужен локальный VS Code и дисплей. Исполняемый файл по умолчанию `/usr/share/code/code`; другой путь задаётся `A11Y_VSCODE`. Это бинарник Electron, не оболочка `code`, которая запускает CLI через `ELECTRON_RUN_AS_NODE`.
- Ожидание теста меняется только если сам критерий ошибочен. Сначала объясняется причина, потом правится тест.
- Таймаут интеграционных тестов — 300 секунд на тест, тесты внутри файла идут по одному.

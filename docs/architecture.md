# Архитектура

`src/core` считает аудит, сопоставление и план правки и не импортирует `vscode`. `src/editorApply.ts` записывает исходники через `WorkspaceEdit`. `src/extension.ts` связывает команды с записью и повторным аудитом. `src/panel.ts` только показывает уже классифицированные проблемы.

## Поток

Проверка идёт так: команда редактора → `auditProject` → поиск Chrome → `detectProject` → запуск приложения → Playwright и axe-core на `127.0.0.1` → `classifyFindings` → `AuditOutcome` → панель. Если браузер не найден, dev-сервер не стартует. Если исполняемый файл не запускается, уже поднятое приложение закрывается до ошибки `NO_CHROME`. Отсутствие axe в странице даёт `AXE_MISSING`, а не пустой список нарушений. `AuditOutcome.url` — адрес открытой страницы, а не только корень dev-сервера. Для динамического маршрута Nuxt без уже существующей ссылки аудит возвращает `NO_ROUTE` и параметр не подбирает.

`nuxt.config.*` выбирается раньше `vite.config.*`. Запуск всегда идёт из корня первой папки workspace. Выбранная папка или файл фильтруют результаты и Quick Fix, но не становятся корнем dev-сервера.

Запись идёт так: кнопка рядом с уже показанным diff → `applyConfirmedEdits` → `planApply` → при отказе файлы не меняются и `WorkspaceEdit` не создаётся → при успехе один `WorkspaceEdit` и `save` → новый аудит.

`applyConfirmedEdits` живёт в `src/editorApply.ts` и может импортировать `vscode`. `src/core` по-прежнему не может. Кнопки «Исправить» и «Исправить все» вызывают её только с подтверждением. Без подтверждения функция сразу возвращается: файл не открывается и `applyEdit` не вызывается. Подтверждённый вызов сравнивает открытый буфер, а если файл не открыт — текст на диске, со снимком аудита. Дальше действует уже посчитанный `planApply`. В `WorkspaceEdit` попадают исходные диапазоны и короткие вставки, не новый текст файла целиком.

Отказ `STALE`, `OVERLAP`, `OUTSIDE_WORKSPACE`, `OUTSIDE_SCOPE` или `UNSAFE` не запускает повторную проверку. После успешного `save` расширение снимает координаты в затронутых файлах и вызывает новый аудит. Если повторная проверка падает, сохранённый текст не откатывается. `npm run test:editor` открывает окно VS Code и проверяет этот путь. Сам axe в этом окне не запускается: хук повторной проверки читает уже сохранённый текст, а в расширении на это место передаётся `audit()`.

На VS Code 1.120 тот же прогон увидел, что один Undo вернул буфер одной правки и оба буфера пакета из двух файлов. Это наблюдение одного прогона, не гарантия продукта.

## Контракты

Менять эти формы можно только вместе с падающим тестом и объяснением, почему прежний контракт неверен.

- `Finding` — сериализуемый узел axe: правило, HTML, цель, метка, проверки, признак incomplete.
- `Issue` — классифицированная проблема: вкладка `quick`, `manual` или `ambiguous`, файл и смещения, `sourceText`, `edits`.
- `TextEdit` — замена `start:end` в конкретном файле.
- `AuditOutcome.files` — полный текст затронутых файлов с диска на момент классификации.
- `ApplyPlan` — либо новые тексты по файлам, либо один отказ на весь пакет: `STALE`, `OVERLAP`, `OUTSIDE_WORKSPACE`, `OUTSIDE_SCOPE`, `UNSAFE`. `UNSAFE` — вставка содержит `alt`, `aria-label`, `aria-labelledby`, `aria-describedby`, `placeholder` или `title`. Такой пакет не записывается целиком. Одинаковые быстрые правки схлопывает `finalizeIssues` до записи.
- `AppHandle.kind` — `vite` или `nuxt`.

Метка в DOM: `data-a11y-source-id="start:end:encodeURIComponent(filename)"`. Она ставится на нативный HTML-узел Vue (`tagType === 0`) и на тег компонента, который этот проект разрешил как Vuetify, Quasar или Nuxt UI. Сопоставление принимает диапазон, если срез файла начинается с `<` и тот же диапазон есть у узла AST. Похожий текст в другом месте файла даёт `unmapped`. Метка не ставится на произвольный компонент: у Vue fallthrough-атрибут родителя перекрывает такую же метку на корне ребёнка, и кнопка из `ChildButton.vue` перестала бы указывать на файл ребёнка.

Причины, которые уже закреплены тестами: `unmapped`, `multiple-instances`, `repeated-source`, `dynamic-attribute`, `bare-bind`.

`Finding` остаётся формой динамического анализа. Статический разбор возвращает `StaticAudit` из `src/core/static.ts`: те же `Issue`, ошибки по файлам и снимок исходника. Оба списка проходят `finalizeIssues`: одинаковые быстрые правки схлопываются, а правка с выдуманным доступным именем теряет diff и становится неоднозначной. Панель по-прежнему показывает только динамический аудит.

## Два запуска Nuxt

Продуктовый путь — `src/core/nuxtHost.ts` и `media/nuxt-runner.mjs`. Раннер загружает Nuxt проекта, слушает `127.0.0.1` через `listhen`, собирает приложение и подключает `media/a11y-nuxt-module.mjs`. Модуль на хуке `vite:extendConfig` добавляет тот же `instrumentPlugin`, что и Vite. На время аудита модуль копируется в `node_modules/.a11y-fixer` и удаляется при `close`. Готовность читается из stdout: `A11Y_MAPPING` и `A11Y_READY`. Селектор страницы — `#__nuxt`. Запасное сопоставление `index.html` для Nuxt выключено.

`experiments/nuxt-source-id` — другое доказательство. Оно запускает `nuxt dev` для Nuxt 3.21.11 и 4.6.4 и проверяет метку в SSR и DOM. axe и `auditProject` оно не вызывает. Этот скрипт сохраняется как `npm run experiment:nuxt` и не заменяет продуктовый раннер.

## Статический анализ

`analyzeVueFiles` читает переданные `.vue` через `@vue/compiler-sfc`, который уже установлен в проверяемом проекте. Свой парсер шаблонов расширение не содержит. Для каждого нативного элемента решение одно из трёх: правило применимо уверенно, правило нельзя довести до конца, элемента это правило не касается.

Уверенно находятся отсутствующий `alt` у `img`, активной `area` и `input type="image"`, пустая кнопка, ссылка с `href`, `iframe` без имени и пустой заголовок, а также целый `tabindex` больше нуля. Последний проходит через уже существующий `buildQuickEdit` и может стать быстрой правкой. Остальные уверенные случаи остаются ручными: текст `alt` и доступное имя не придумываются.

Неоднозначно и без правки: `v-for`, объектный `v-bind`, динамический атрибут, текст из `{{ }}`, содержимое компонента, слота или `v-html`, `aria-labelledby` без статической цели в этом файле. Единственный корневой элемент не даёт ручного вывода об отсутствующем `alt` или имени, потому что атрибут может прийти от родителя. Статический `tabindex` на этом корне по-прежнему может быть быстрой правкой.

Ошибка одного файла остаётся в `errors` и не отменяет остальные. Шаблон не на HTML, например Pug, не разбирается как HTML. Отсутствие компилятора Vue даёт `NO_VUE_COMPILER`. Каталоги `node_modules`, `dist`, `build`, `.git`, `.nuxt` и `.output` не входят в `listVueFiles`.

Статически не решаются подпись поля и `autoplay`. Кнопка «Проверить» по-прежнему показывает динамический аудит. Статический разбор библиотек живёт в `analyzeVueFiles` и в панель отдельно не выводится.

## Vuetify, Quasar и Nuxt UI

Расширение не подключает эти библиотеки. Каталог в `src/core/libraries.ts` сверен с установленными пакетами и применяется только к точной версии:

| Пакет | Версия | Компоненты |
| --- | --- | --- |
| `vuetify` | 3.13.7 | `VBtn` / `v-btn`, `VImg` / `v-img` |
| `quasar` | 2.35.5 | `QBtn` / `q-btn`, `QImg` / `q-img` |
| `@nuxt/ui` | 4.12.2 | `UButton` / `u-button` |

Компонент считается библиотечным, если версия в `node_modules` совпала, тег не перекрыт локальным `.vue` или импортом из другого модуля, и регистрация доказана. Доказательство — импорт из пакета библиотеки либо стандартная регистрация: `vite-plugin-vuetify` без `autoImport: false`, `@quasar/vite-plugin` без `astAutoImport: false`, модуль `@nuxt/ui` или плагин `@nuxt/ui/vite` без `components: false`. У плагина Quasar режим по умолчанию `kebab`: без `autoImportComponentCase: 'pascal'` или `'combined'` узнаётся `<q-btn>`, а не `<QBtn>`. Явный импорт узнаёт оба написания. Другая версия, локальный компонент и неизвестный тег не дают находки.

Имя кнопки берётся из статического текста слота, `aria-label`, `title`, разрешённого в файле `aria-labelledby`, а также из `label` у Quasar и Nuxt UI и из строкового или числового `text` у `VBtn`, когда иконка его не вытесняет. Булев `text` у `VBtn` тоже даёт текст: `toDisplayString(true)` выводит `true`. Имя иконки и `QTooltip` именем не считаются. `href` или непустой `to` дают `link-name`; пустой `href` у `VBtn` и `UButton` остаётся кнопкой, у `QBtn` присутствие `href`, даже пустого, даёт ссылку. `QBtn` с `type="a"` без `href` остаётся кнопкой: библиотека ставит `role="button"`. У `QBtn` непустой `to` становится ссылкой только при наличии `$router`, а у `VBtn` без зарегистрированного `RouterLink` тот же `to` даёт `<a>` без `href`. Статический разбор этого окружения не видит и всё равно ставит `link-name`. Текст `alt` и подпись не придумываются.

У `VImg` отсутствующий `alt` — ручной `image-alt`. `alt=""` находки не даёт. `role` на компоненте до внутреннего `img` не доходит, поэтому `role="presentation"` отсутствие `alt` не отменяет. У `QImg` 2.35.5 отсутствующий `alt` — декоративное изображение: внутренний `img` получает `alt=""` и `aria-hidden`. Находки нет.

Целый `tabindex` больше нуля становится быстрой правкой у `VBtn` и `QBtn`. У `VBtn` 3.13.7 атрибут доходит до корневой кнопки или ссылки через fallthrough Vue 3.5. У `QBtn` проп `tabindex` пишется на корень. У `UButton` цепочка `ULink` → `ULinkBase` → Primitive в статический каталог не включена, быстрой правки нет. Динамический аудит всё же сопоставил пустую `UButton` с тегом в SFC: метка дошла до кнопки, и axe дал ручной `button-name`.

Остальные компоненты этих библиотек не разбираются. Vuetify 2, Vuetify 4 и Nuxt UI 2/3 в каталог не входят.

## Ограничения, которые остаются

- Динамический аудит требует конфиг Vite или Nuxt и Chrome. Браузер проверяется до старта dev-сервера. Статический разбор `.vue` запускает только компилятор проекта.
- Повторный аудит Vite сбрасывает module graph. У Nuxt `invalidate()` пустой, поэтому повтор после правки может увидеть старый бандл.
- Продуктовая регрессия покрывает Nuxt 3.21.11. Продуктовый путь Nuxt 4 отдельным тестом не закреплён.
- Разобраны только перечисленные компоненты Vuetify 3.13.7, Quasar 2.35.5 и Nuxt UI 4.12.2. Метка по-прежнему стоит на нативном HTML внутри своего SFC. Произвольный компонент её не получает.
- Исключения каталогов заданы константой: `node_modules`, `dist`, `build`, `.git`, `.nuxt`, `.output`.
- Отчёт Markdown и JSON пишется через `fs` в `a11y-fixer-report.md`. Это единственная запись мимо `WorkspaceEdit`.
- Открывается одна папка workspace.

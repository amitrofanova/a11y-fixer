# Архитектура

Расширение делится на три слоя. `src/core` считает аудит, сопоставление и план правки и не импортирует `vscode`. `src/extension.ts` вызывает этот слой и записывает исходники через `WorkspaceEdit`. `src/panel.ts` только показывает уже классифицированные проблемы.

## Поток

Проверка идёт так: команда редактора → `auditProject` → поиск Chrome → `detectProject` → запуск приложения → Playwright и axe-core на `127.0.0.1` → `classifyFindings` → `AuditOutcome` → панель. Если браузер не найден, dev-сервер не стартует. Если исполняемый файл не запускается, уже поднятое приложение закрывается до ошибки `NO_CHROME`. Отсутствие axe в странице даёт `AXE_MISSING`, а не пустой список нарушений. `AuditOutcome.url` — адрес открытой страницы, а не только корень dev-сервера. Для динамического маршрута Nuxt без уже существующей ссылки аудит возвращает `NO_ROUTE` и параметр не подбирает.

`nuxt.config.*` выбирается раньше `vite.config.*`. Запуск всегда идёт из корня первой папки workspace. Выбранная папка или файл фильтруют результаты и Quick Fix, но не становятся корнем dev-сервера.

Запись идёт так: выбранные `edits` → `planApply` → при отказе файлы не меняются → при успехе один `WorkspaceEdit` и `save` → новый аудит.

## Контракты

Менять эти формы можно только вместе с падающим тестом и объяснением, почему прежний контракт неверен.

- `Finding` — сериализуемый узел axe: правило, HTML, цель, метка, проверки, признак incomplete.
- `Issue` — классифицированная проблема: вкладка `quick`, `manual` или `ambiguous`, файл и смещения, `sourceText`, `edits`.
- `TextEdit` — замена `start:end` в конкретном файле.
- `AuditOutcome.files` — полный текст затронутых файлов с диска на момент классификации.
- `ApplyPlan` — либо новые тексты по файлам, либо один отказ на весь пакет: `STALE`, `OVERLAP`, `OUTSIDE_WORKSPACE`, `OUTSIDE_SCOPE`.
- `AppHandle.kind` — `vite` или `nuxt`.

Метка в DOM: `data-a11y-source-id="start:end:encodeURIComponent(filename)"`. Она ставится только на нативный HTML-узел Vue (`tagType === 0`). Сопоставление принимает диапазон, если срез файла начинается с `<` и тот же диапазон есть у узла AST. Похожий текст в другом месте файла даёт `unmapped`.

Причины, которые уже закреплены тестами: `unmapped`, `multiple-instances`, `repeated-source`, `dynamic-attribute`, `bare-bind`.

`Finding` остаётся формой динамического анализа. Статический разбор возвращает `StaticAudit` из `src/core/static.ts`: те же `Issue`, ошибки по файлам и снимок исходника. Панель по-прежнему показывает только динамический аудит.

## Два запуска Nuxt

Продуктовый путь — `src/core/nuxtHost.ts` и `media/nuxt-runner.mjs`. Раннер загружает Nuxt проекта, слушает `127.0.0.1` через `listhen`, собирает приложение и подключает `media/a11y-nuxt-module.mjs`. Модуль на хуке `vite:extendConfig` добавляет тот же `instrumentPlugin`, что и Vite. На время аудита модуль копируется в `node_modules/.a11y-fixer` и удаляется при `close`. Готовность читается из stdout: `A11Y_MAPPING` и `A11Y_READY`. Селектор страницы — `#__nuxt`. Запасное сопоставление `index.html` для Nuxt выключено.

`experiments/nuxt-source-id` — другое доказательство. Оно запускает `nuxt dev` для Nuxt 3.21.11 и 4.6.4 и проверяет метку в SSR и DOM. axe и `auditProject` оно не вызывает. Этот скрипт сохраняется как `npm run experiment:nuxt` и не заменяет продуктовый раннер.

## Статический анализ

`analyzeVueFiles` читает переданные `.vue` через `@vue/compiler-sfc`, который уже установлен в проверяемом проекте. Свой парсер шаблонов расширение не содержит. Для каждого нативного элемента решение одно из трёх: правило применимо уверенно, правило нельзя довести до конца, элемента это правило не касается.

Уверенно находятся отсутствующий `alt` у `img`, активной `area` и `input type="image"`, пустая кнопка, ссылка с `href`, `iframe` без имени и пустой заголовок, а также целый `tabindex` больше нуля. Последний проходит через уже существующий `buildQuickEdit` и может стать быстрой правкой. Остальные уверенные случаи остаются ручными: текст `alt` и доступное имя не придумываются.

Неоднозначно и без правки: `v-for`, объектный `v-bind`, динамический атрибут, текст из `{{ }}`, содержимое компонента, слота или `v-html`, `aria-labelledby` без статической цели в этом файле. Единственный корневой элемент не даёт ручного вывода об отсутствующем `alt` или имени, потому что атрибут может прийти от родителя. Статический `tabindex` на этом корне по-прежнему может быть быстрой правкой.

Ошибка одного файла остаётся в `errors` и не отменяет остальные. Шаблон не на HTML, например Pug, не разбирается как HTML. Отсутствие компилятора Vue даёт `NO_VUE_COMPILER`. Каталоги `node_modules`, `dist`, `build`, `.git`, `.nuxt` и `.output` не входят в `listVueFiles`.

Статически не решаются подпись поля, `autoplay` и семантика Vuetify, Nuxt UI, Quasar: по одному SFC это нельзя установить надёжно. Кнопка «Проверить» этот разбор пока не показывает.

## Ограничения, которые остаются

- Динамический аудит требует конфиг Vite или Nuxt и Chrome. Браузер проверяется до старта dev-сервера. Статический разбор `.vue` запускает только компилятор проекта.
- Повторный аудит Vite сбрасывает module graph. У Nuxt `invalidate()` пустой, поэтому повтор после правки может увидеть старый бандл.
- Продуктовая регрессия покрывает Nuxt 3.21.11. Продуктовый путь Nuxt 4 отдельным тестом не закреплён.
- Семантика компонентных библиотек не выводится. Метка ставится на нативный HTML, в том числе на HTML внутри дочернего SFC.
- Исключения каталогов заданы константой: `node_modules`, `dist`, `build`, `.git`, `.nuxt`, `.output`.
- Отчёт Markdown и JSON пишется через `fs` в `a11y-fixer-report.md`. Это единственная запись мимо `WorkspaceEdit`.
- Открывается одна папка workspace.

# A11y Fixer: review прототипа, контракт безопасности, MVP

Документ фиксирует, что уже доказано кодом, при каких условиях расширение имеет право менять файлы, и что обязано работать в первой версии. Архитектура source mapping и набор быстрых правил здесь не пересматриваются.

Прототип проверен на демо Vue 3 + Vite: Vite 8.3.5, Vue 3.5.44, `@vitejs/plugin-vue` 6.0.10, axe-core 4.14.0.

Динамический аудит Nuxt идёт через `startNuxtApp`: отдельный процесс делает `loadNuxt`, `listhen` и `buildNuxt`. `npm run test:nuxt` закрепляет этот путь на Nuxt 3.21.11. Nuxt 4 в этом прогоне нет. Метка на Nuxt 3.21.11 и 4.6.4 дополнительно доказана экспериментом `npm run experiment:nuxt`, который запускает `nuxt dev` и не вызывает axe.

Статический разбор `.vue` живёт в `analyzeVueFiles` и не запускает приложение. Панель его пока не показывает. Подпись поля и `autoplay` по одному SFC не выводятся. Из библиотек статически разобраны только `VBtn`, `VImg`, `QBtn`, `QImg` и `UButton` сверенных версий: Vuetify 3.13.7, Quasar 2.35.5, Nuxt UI 4.12.2.

## 1. Архитектурный review

### Модули

| Модуль | Файлы | Ответственность | Зависимости |
| --- | --- | --- | --- |
| `core` | `src/core/*` | Запуск Vite и Nuxt, инструментирование шаблона, axe-core, сопоставление DOM → исходник, классификация вкладок, расчёт правки, отчёт | Node, Playwright, axe-core, Vite или Nuxt проекта и его Vue-компилятор. Не импортирует `vscode` |
| `extension` | `src/extension.ts` | Команды, снимок файлов, запись через `WorkspaceEdit`, повторный аудит после записи | `core`, `panel`, VS Code API |
| `panel` | `src/panel.ts`, `media/panel.*` | Три вкладки, diff, кнопки. Не считает правки и не пишет файлы | VS Code Webview. Получает уже классифицированные issues |
| `i18n` | `src/i18n.ts` | Строки интерфейса ru/en | Нет |
| tests | `test/unit`, `test/integration` | Контракты и регрессии Vite/Nuxt без окна редактора | `node:test`, `core` |

Граница в целом соблюдена: бизнес-логика вкладок и патчей живёт в `core`, отображение — в `panel`, запись в workspace — в `extension`. Отказ `STALE` / `OVERLAP` / `OUTSIDE_WORKSPACE` / `OUTSIDE_SCOPE` считает `planApply` и при отказе не отдаёт замены. Редактор после успешного плана пишет через `WorkspaceEdit`. Vite-регрессия применяет уже посчитанный текст через `fs` во временной копии `demo/`, поэтому путь `WorkspaceEdit` она не доказывает.

Собственного Undo нет. Штатный Ctrl+Z не блокируется и не обещается.

`core` не знает про Webview. Он возвращает `AuditOutcome`: список issues, снимок затронутых файлов, флаг `mappingEnabled`.

Снимок `outcome.files` — это текст с диска на момент классификации (`fs.readFileSync`). Несохранённый буфер редактора в аудит не входит. При записи сравнивается текущий буфер, если файл открыт, иначе диск. Несохранённые правки, не совпадающие со снимком, дают `STALE`. Проверка всегда смотрит сохранённый исходник.

### Поток данных

```text
Проверить
  → extension.audit
  → core.auditProject
      Vite createServer + nodeTransform
      Playwright Chromium на 127.0.0.1
      axe-core в странице
      Finding { ruleId, marker, html, checks }
  → core.classifyFindings
      locateMarker | locateHtmlFallback
      tab = quick | manual | ambiguous
      для quick: TextEdit[] + before/after
  → AuditOutcome
  → (позже) фильтр области аудита
  → panel.postMessage
  → Webview
```

Запись:

```text
Исправить / Исправить все
  → только issues с tab=quick, непустым edits и файлом внутри области аудита
  → файл внутри workspace и корня Vite-проекта
  → буфер редактора == снимок аудита
  → applyTextEdits на снимке; пересечение → отказ
  → WorkspaceEdit + save
  → дождаться совпадения буфера и диска
  → новый auditProject
  → новая панель
```

После любой успешной записи координаты этого результата больше не используются. Следующее «Показать в коде» и следующая правка идут только из нового аудита.

### Source mapping

Метка на нативном HTML-узле Vue SFC:

```text
data-a11y-source-id = start:end:encodeURIComponent(filename)
```

Она появляется только если найден `vite:vue` с `api.options`. Иначе `mappingEnabled=false`, быстрые правки в компонентах не предлагаются.

Обратный путь: прочитать метку с DOM → открыть файл из метки, только внутри корня проекта → `source.slice(start,end)` должен начинаться с `<` → тот же диапазон должен существовать в AST шаблона. Один исходный узел и несколько DOM-элементов (`v-for`) дают вкладку «неоднозначные».

Запасной путь без метки: единственный подходящий тег в корневом `index.html` для `meta-viewport`, `body`, `html`, `title`.

Связь надёжна для обычного статического HTML внутри SFC при инструментированной сборке расширения. Она не обещает слоты, `v-html`, JSX, компоненты из `node_modules`, SSR и уже запущенный dev-сервер пользователя.

### Quick fixes

Правила и патчи заданы в `src/core/source.ts`. Текст `alt` и доступных имён программа не придумывает.

| Правило | Патч | Условие отказа |
| --- | --- | --- |
| `scrollable-region-focusable` | вставить `tabindex="0"` | атрибут уже есть, `v-bind`, `v-for` |
| `tabindex` | заменить положительное значение на `0` | нет статического атрибута, значение не целое > 0 |
| `no-autoplay-audio` | удалить `autoplay` | нет статического атрибута |
| `aria-prohibited-attr` | удалить имена из `checks[].data.prohibited` | список пуст, атрибут динамический |
| `aria-hidden-body` | удалить `aria-hidden` у `body` | нет единственного `body` |
| `meta-viewport`, `meta-viewport-large` | убрать `user-scalable=no` и `maximum-scale < 5` | нет единственного viewport |

Ручная вкладка: найден ровно один статический узел, но значение должен выбрать человек (`image-alt`, `button-name`, имена ссылок и полей, язык, заголовок документа и т.д.). Записи нет.

Неоднозначная вкладка: нет метки, несколько экземпляров, `v-for`, динамический атрибут, `v-html`, неизвестное правило, включая контраст и структуру страницы.

### Ошибки сейчас

| Ситуация | Поведение |
| --- | --- |
| Нет `vite.config.*` в корне workspace | `NO_VITE_CONFIG`, файлы не меняются |
| Нет Chrome/Chromium | `NO_CHROME` |
| Сервер слушает не `127.0.0.1` | `NO_PORT`, сервер закрывается |
| Нет `#app` после загрузки | повтор до трёх раз, затем ошибка Playwright |
| Нет `api.options` у `vite:vue` | аудит идёт, точных правок в SFC нет |
| Буфер ≠ снимок аудита | `STALE`, запись не начинается |
| Диапазоны в одном файле пересекаются | `OVERLAP`, ни один файл пакета не пишется |
| `WorkspaceEdit` или save не прошли | `APPLY_FAILED` / `SAVE_FAILED` |
| Повторный аудит после правки, проблема осталась | она снова в списке; автоматического отката нет |
| Запись прошла, повторный аудит упал | координаты оставшихся issues в затронутых файлах уже сняты |
| Отмена проверки | нет. Повторный запуск встаёт в очередь |
| Аварийное завершение | `deactivate` закрывает браузер и Vite |
| Incomplete axe, не быстрое правило | не показывается |
| «Исправить все» и «Исправить все и перезапустить проверку» | один путь: запись пакета, затем новый аудит |

В прототипе дополнительно есть стек собственного Undo. Для MVP это не требование и не часть контракта записи.

Необработанные сбои Vite/Playwright приходят сырым текстом ошибки. Отчёт пишется через `fs.writeFileSync` в `a11y-fixer-report.md`, минуя `WorkspaceEdit`. Это единственная запись файла вне контракта правок.

`settleDocument` ждёт совпадения буфера и диска не дольше ~400 мс. Это нужно, чтобы повторный аудит увидел тот же текст, что видит пользователь после format-on-save. Это не механизм Undo.

## 2. Контракт безопасности Quick Fixes

Расширение меняет файл только если все условия ниже истинны. Иначе обязано отказаться. Собственный Undo в этот контракт не входит. Отказ от него не ослабляет защиту: запись по-прежнему запрещена, если исходник устарел, диапазоны пересеклись, файл вне workspace или вне области аудита.

### Право на запись

1. Пользователь нажал «Исправить», «Исправить все» или «Исправить все и перезапустить проверку».
2. У нарушения `tab === 'quick'` и непустой список `edits`.
3. Каждый `edit.file` непосредственно перед записью лежит внутри workspace и внутри корня Vite-проекта. На сопоставление метки на предыдущем этапе не полагаемся.
4. Если задана область аудита, каждый `edit.file` лежит внутри неё и не попадает в исключённые каталоги.
5. Текст открытого буфера (если файл открыт) или текст на диске в точности равен снимку `outcome.files[file]`, сделанному во время аудита, из которого взята эта правка.
6. Все правки пакета проходят проверку на пересечение. Одинаковые правки (`file+start+end+insert`) схлопываются. Пересекающиеся диапазоны не объединяются и не записываются. Соседние, но не пересекающиеся диапазоны (`end === start` другого) допустимы.
7. Diff уже показан в панели до нажатия. Отдельного сводного диалога нет: карточки быстрых правок с `before`/`after` и есть preview пакета, в том числе по нескольким файлам.
8. Запись исходников идёт только через `WorkspaceEdit` и последующий `save`. Прямая запись исходников через `fs` запрещена. Отчёт — исключение, см. выше.
9. После записи расширение не делает дополнительных подмен файла «поверх» `WorkspaceEdit`. Иначе будет сломан штатный Ctrl+Z редактора.

### Отказ

| Ситуация | Поведение |
| --- | --- |
| Файл не менялся после аудита | Записать после подтверждения |
| Файл или буфер отличается от снимка | Не записывать. Сообщить, что нужна новая проверка |
| Несколько непересекающихся правок одного файла | Один `WorkspaceEdit` |
| Диапазоны пересекаются | Не записывать ни этот файл, ни остальные файлы пакета |
| Файл вне workspace, вне корня Vite-проекта, вне области аудита или в исключённом каталоге | Не записывать весь пакет |
| Нет точного сопоставления | Только диагностика, без кнопки записи |
| `v-for`, слот, `v-html`, динамический атрибут, библиотечный компонент | Не записывать |
| Нужен новый текст от человека | Ручная вкладка, без записи |

Изменение исходника после аудита определяется полным сравнением текста, не хешем и не версией документа VS Code. Хеш совпал бы с полным текстом, но не показал бы, что именно изменилось. Версия документа не ловит правку на диске вне редактора и ломается на format-on-save. Снимок — диск на момент классификации. Перед записью сравнивается буфер, если файл открыт: именно его меняет `WorkspaceEdit`.

### Отмена после записи

Собственного Undo нет.

Пользователь может пользоваться штатным Ctrl+Z VS Code. Продукт не должен ему мешать: один `WorkspaceEdit` на партию, без повторной записи целого файла и без собственного стека снимков.

Это не гарантия продукта. Не обещаем, что один Ctrl+Z откатит всю партию, особенно если затронуто несколько файлов или сработал format-on-save. Поведение нужно проверить экспериментально на пакетной записи. Пока не доказано — не пишем в критерии приёмки.

Если пользователь изменил файл после нашей записи, следующая правка из старого результата запрещена (`STALE`). Новые координаты появляются только после нового аудита.

### Что считается успехом

| Этап | Критерий |
| --- | --- |
| Применение | `WorkspaceEdit` принят, файл сохранён, буфер совпал с диском |
| Устранение проблемы | Повторный аудит больше не ставит то же правило в быстрые правки для этого узла |
| Неуспех правки | Повторный аудит снова показывает правило. Автоматического отката нет |

Запись текста сама по себе не считается исправленной доступностью.

### Решения, которые принимаем

1. Снимок — полный текст файла с диска на момент классификации, не хеш и не `TextDocument.version`.
2. Пересекающиеся диапазоны — отказ всего пакета. Автослияние таких правок не делаем: оно скрывает конфликт и собирает патч, которого пользователь не видел.
3. Основной механизм записи исходников — `WorkspaceEdit`. После `applyEdit` и `save` файл больше не перезаписываем целиком.
4. Принадлежность файла workspace и области аудита проверяется в политике применения, сразу перед расчётом новых текстов, а не только в source mapping.
5. Успех для пользователя — повторная проверка. Кнопки «Исправить все» и «Исправить все и перезапустить проверку» после записи обе запускают новый аудит.
6. Собственный Undo не входит в MVP. Штатный Ctrl+Z не мешаем и не обещаем.

## 3. Критерии приёмки MVP

Первая версия обещает только это.

### Обязано работать

- Локально, без внешних сервисов. Браузер только на `127.0.0.1`.
- Vue 3 + Vite в корне открытой папки: обычные SFC и корневой `index.html`.
- Nuxt 3 в корне открытой папки: динамический аудит запущенного приложения. Продуктовая регрессия закреплена на 3.21.11. Повторный аудит Nuxt после правки не обещан: `invalidate()` у Nuxt пустой.
- Ручной запуск проверки. Скрытый Chromium. Язык панели по языку VS Code: ru или en.
- Три вкладки, сортировка `critical → serious → moderate → minor`, затем файл и смещение.
- Сопоставление обычного статического HTML в шаблоне через compile-time id.
- Быстрые патчи из таблицы выше, только после кнопки, с diff.
- Ручные нарушения: описание и «Показать в коде», без записи.
- `v-for` и отсутствие метки — неоднозначные, без записи.
- «Показать в коде» выделяет фрагмент, который в текущем буфере совпадает с `sourceText`. Если буфер сдвинут, ищется ближайшее точное вхождение этого текста.
- «Исправить все» применяет все текущие быстрые правки по одному снимку, затем один новый аудит.
- Отчёт Markdown + JSON в `a11y-fixer-report.md` по всем трём вкладкам. Отчёт файлы проекта не чинит.
- Отказ записи, если буфер изменился после аудита, диапазоны пересеклись или файл вне workspace.
- Повторная проверка после записи. Если быстрая проблема осталась, она снова в списке.

### Сознательно не обещаем

Собственный Undo, гарантию одного Ctrl+Z на всю партию, видимый браузер, CSS/SCSS, авторизация и чужой уже запущенный dev-сервер, JSX, Vapor, Angular, React, компоненты из зависимостей, слоты как место правки, придуманный `alt`/`aria-label`, контраст, размер цели, порядок заголовков, история проверок, AI, переключатель WCAG, отмена идущего аудита, несколько workspace folder.

Пустой список нарушений не означает соответствие WCAG. Nuxt 4 через `startNuxtApp` в продуктовую регрессию не входит. Поддержка UI-библиотек ограничена компонентами и версиями из `docs/architecture.md`. Остальные компоненты Vuetify, Quasar и Nuxt UI не разбираются.

Выбор папки больше не отложен «на потом». Он не входит в обязательный список демо-MVP, но это следующая итерация после контракта записи. См. раздел 4.

Демо `#app` — условие текущего запуска, не контракт всех Vue-проектов.

## 4. Область аудита и контекст запуска

Выбор папки — не смена корня Vite и не способ проверить файлы, которые не попали в DOM. Это отдельная граница поверх уже работающего запуска приложения.

| Понятие | Значение |
| --- | --- |
| Контекст запуска | Весь Vue-проект с `vite.config.*`. Его запускают Vite, Playwright и axe-core, чтобы получить реальный DOM |
| Область аудита | Папка или файл, выбранные пользователем. По ним фильтруются результаты и Quick Fix |
| Область применения | Подмножество области аудита: файлы, которые политика имеет право изменить |

Следствия:

- Приложение всегда стартует целиком. Неиспользуемые компоненты выбранной папки не отрисуются и не появятся в axe-core.
- Выбор `src/components` не означает «проверить каждый `.vue` внутри». Он означает «из найденного в DOM оставить то, что принадлежит этой папке».
- Нарушение в общем компоненте вне папки не должно попасть в «Исправить все». Его можно показать как вне области, без кнопки записи.
- Фильтр не ускоряет аудит: Playwright и axe-core по-прежнему обходят загруженную страницу.

Исключения по умолчанию, настраивать позже: `node_modules`, `dist`, `build`, `.git`. Файл в таком каталоге не входит ни в область аудита, ни в область применения.

Если файл у нарушения не определён, его нельзя считать принадлежащим выбранной папке. В режиме папки такие находки не входят в Quick Fix. Их можно показать отдельно как «без файла», чтобы были видны дыры mapping, но не смешивать с исправлениями папки.

Работа начинается с выбора области, а не с проверки всего проекта:

1. Кнопка «Выбрать файлы для проверки» в панели или команда в заголовке вида.
2. Либо контекстное меню «Проверить доступность» на папке или файле в проводнике.
3. Vite по-прежнему запускает всё приложение из корня проекта.
4. Результаты и Quick Fix фильтруются по выбранной папке или файлу.
5. Можно отдельно запустить проверку всего проекта.

Выбор нескольких файлов сразу в этой итерации не обещаем.

## 5. Risk-based test matrix

`npm run check` покрывает unit-контракты и Vite-регрессию: пакет быстрых правок, правки по одной с аудитом после каждой, отказ захватывать предыдущий тег после переформатирования, неизменность ручной кнопки и `v-for`. `planApply` в unit-тестах при отказе не меняет файл. Запись Vite-регрессии идёт через `fs` во временную копию, поэтому отказ редактора через `WorkspaceEdit` этим прогоном не доказан. `npm run test:nuxt` отдельно проверяет первый аудит Nuxt 3.21.11.

### Срез 1. Политика применения

Чистая функция в `core`, без `vscode` и без стека Undo.

Вход:

- корень workspace и корень Vite-проекта;
- необязательная область аудита;
- снимок файлов аудита;
- текущие тексты тех же файлов;
- список `TextEdit`.

Выход:

- либо дедуплицированные правки и новые тексты по файлам;
- либо отказ `STALE` / `OVERLAP` / `OUTSIDE_WORKSPACE` / `OUTSIDE_SCOPE`.

Функция проверяет принадлежность файлов, сравнивает тексты, отбрасывает дубликаты, считает новые содержимые. Она не пишет диск.

`extension.ts` только спрашивает текущий буфер, вызывает политику, при `ok` делает `WorkspaceEdit` по исходным диапазонам, сохраняет, ждёт settle, запускает новый аудит. Стек собственного Undo удаляется.

`self-check` переводится на ту же функцию: `STALE`, `OVERLAP`, вне корня, пакет и одиночная правка. Для отказа проверка должна убедиться, что текст файла не изменился.

Интеграция с VS Code: редактор использует ту же функцию; при отказе `WorkspaceEdit` не создаётся. Отдельно смотрим, не ломает ли текущая запись штатный Ctrl+Z на одном файле и на пакете. Результат эксперимента фиксируем, в гарантию не превращаем.

### Срезы 3–4. Папка

Сначала только граница анализа: контекстное меню, фильтр, подпись области в панели, возврат ко всему проекту, без Quick Fix в этом режиме.

Затем область применения: политика отклоняет файлы вне папки, «Исправить все» их не видит.

Срезы 1–3 реализованы: политика в `src/core/apply.ts`, тесты и расширение используют `planApply`, собственный Undo удалён, папка фильтрует результаты, Quick Fix проходит ту же политику с `auditScope`. Прежний `src/selfCheck.ts` заменён unit-тестами и Vite-регрессией на временной копии `demo/`. Продуктовый Nuxt 3 покрыт `npm run test:nuxt`.
